= `i2code ctl` -- Supervise a Running Implement

== Group Help

Observe and steer a running `i2code implement`.

`i2code implement` (worktree mode) writes a run journal for each idea under the git common directory:
`<git common dir>/i2code/implement/<idea>/` holds `events.jsonl` (append-only, one JSON object per line) and
`status.json` (the current state, folded from the events). The directory is inside `.git`, so it is never
committed, and it is the same from the main checkout and from the idea worktree.

`IDEA` is an idea name or an idea directory path, as for `implement`. Run `ctl` from anywhere inside the repository.

== Subcommands

=== `status`

[source,shell]
----
i2code ctl status IDEA [--json]
----

Prints the run state (`running`, `ci_wait`, `blocked`, `completed`, `stopped`, `failed`), the pid and whether it is
alive, the current task, the Claude invocation in progress and the last one, the block reason with the commands
that resume or stop the run, and the path of `events.jsonl`.
A run whose pid is gone before it reached a final state is shown as `dead`.

`--json` prints `status.json` plus `alive`, `queued_notes` and `events_file`.

=== `events`

[source,shell]
----
i2code ctl events IDEA [--limit N] [--follow]
----

Prints the last `N` events (default 20) as JSON lines.
`--follow` keeps printing new events and exits after a `run_finished` event, so a supervising session can wait
on it with a monitor.

=== `note`

[source,shell]
----
i2code ctl note IDEA TEXT
----

Queues a note in the run's inbox (allowed even when nothing is running).
Before its next Claude invocation labelled `task`, `ci_fix`, `fix_feedback`, `nudge` or `resume`, the run removes
the queued notes and appends them to the prompt:

----
Notes from the supervising session (oldest first):
- <note>
----

`status` shows how many notes are still queued.

=== `resume`

[source,shell]
----
i2code ctl resume IDEA [--note TEXT] [--fresh]
----

Resumes a run that is blocked (`implement --on-failure wait`).
By default the blocked Claude session continues (`claude --resume`) with a prompt that carries `--note`;
`--fresh` (or a failure without a session id) starts the task again in a new session, with the note after the task prompt.
The result is validated as usual; if it fails again, the run blocks again.
A run blocked on exhausted CI-fix retries runs the CI fix loop again with a fresh budget, with the note added to the
next CI-fix prompt; a run blocked on a failed push pushes again (the note is not used there — queue it with `note`).
Exits 1 without doing anything when the run is not alive or not blocked.

=== `stop`

[source,shell]
----
i2code ctl stop IDEA
----

Asks the run to stop gracefully. The run checks for the request between tasks, in the review poll loop and while
blocked, then journals `stop_requested` and `run_finished` (`stopped`) and exits 0. A Claude invocation that is
already running is not interrupted. Exits 1 when no live run exists.
When a run starts, `resume` and `stop` requests left by an earlier run are discarded; queued notes are kept.

== Events

[cols="1,3",options="header"]
|===
| Event | Fields

| `run_started` | `pid`, `idea`, `branch`, `worktree`
| `task_started` | `task`, `title`, `index`, `total`
| `claude_started` | `label`, `resumes_session`
| `claude_finished` | `label`, `exit_code`, `outcome` (`success`, `failure`, `missing`), `session_id`, `num_turns`, `cost_usd`, `duration_s`, `summary`
| `note_delivered` | `label`, `count`
| `task_completed` | `task`, `duration_s`, `head`
| `pushed` | `head`
| `ci_waiting` / `ci_finished` | `head` / `head`, `success`, `failing_workflow`
| `blocked` | `kind` (`task`, `ci_fix`, `push`), `reason` (`failure_tag`, `missing_tag`, `attempts_exhausted`, `ci_retries_exhausted`, `push_failed`; after a resume also `no_commit`, `not_marked_complete`, `no_ci_workflow`), `task`, `detail`, `session_id`, `permission_denials`
| `resumed` | `mode` (`continue`, `fresh`), `note`
| `stop_requested` | —
| `run_finished` | `status` (`completed`, `stopped`, `failed`), `exit_code`
|===

Every event also has `ts` (ISO 8601 with UTC offset) and `event`.

== Examples

[source,shell]
----
i2code ctl status my-feature
i2code ctl status my-feature --json | jq .state
i2code ctl events my-feature --follow | grep --line-buffered -E '"(blocked|task_completed|run_finished)"'
----
