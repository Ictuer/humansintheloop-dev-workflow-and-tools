= `i2code implement` -- Plan Implementation

== Command Help

Implement a development plan using Git worktrees and GitHub Draft PRs.

== Usage

[source,shell]
----
i2code implement <idea-directory> [options]
----

== Parameters

`<idea-directory>`::
Directory containing the plan file and related idea artifacts.

== Options

`--cleanup`::
Remove worktree and delete local branches after the PR is merged or closed.

`--setup-only`::
Only set up infrastructure (branches, worktree, PR) without executing tasks.

`--non-interactive`::
Run Claude in non-interactive mode (uses the `-p` flag).

`--extra-prompt TEXT`::
Extra text to append to Claude's prompt (after a blank line).

`--extra-prompt-file PATH`::
Read the extra prompt text from a UTF-8 file. Cannot be combined with `--extra-prompt`.

`--claude-args TEXT`::
Extra arguments appended to every `claude` invocation (task, CI fix, review, recovery), split like a shell, for example `--claude-args "--effort high"`.
Flags that i2code sets itself (`-p`, `--print`, `--output-format`, `-r`/`--resume`, `-c`/`--continue`, `--fork-session`, `--session-id`, `--allowedTools`/`--allowed-tools`) are rejected.
In interactive mode the prompt follows these arguments as a positional argument, so do not end them with a flag that takes values (such as `--add-dir DIR`).

`--on-failure exit|wait`::
What a worktree-mode run does when a task fails, CI-fix retries run out, or a push fails (default `exit`, the previous behaviour).
With `wait` the run becomes _blocked_ instead of exiting: it records why in its journal, prints the `i2code ctl` commands to use, and waits for `i2code ctl resume` (continue the blocked Claude session, or `--fresh` for a new one, optionally with `--note`) or `i2code ctl stop`.
An explicit `<FAILURE>` blocks at once instead of being retried in a new session.
See link:ctl.adoc[`i2code ctl`]. Cannot be combined with `--trunk` or `--isolate`.

`--nudge-missing-tag N`::
Non-interactive worktree mode: when Claude exits cleanly but its final message has neither `<SUCCESS>` nor `<FAILURE>`, resume the same session (`--resume`) and ask it to finish with a tag, up to `N` times per attempt (default 0).
Covers sessions that end their turn while something still runs in the background, such as waiting for CI.

`--resume-on-api-error N`::
Non-interactive worktree mode: when a task invocation fails with a temporary Claude API error (`API Error: ...`, for example `529 Overloaded` or a lost connection), wait 60 s, 120 s, 240 s, ... (at most 15 minutes) and resume the same session up to `N` times per attempt instead of starting a new session (default 0).

`--allow-push`::
Let Claude push the idea branch to `origin` during a task (never with `--force`, never another branch), for tasks that need CI to run on a new commit before they can finish.
The worktree's `.claude/settings.local.json` gets no `Bash(git push:*)` deny rule, and the task prompt allows the push. i2code still pushes after each task.

`--trunk`::
Execute tasks locally on the current branch (no worktree, PR, or CI).

`--skip-ci-wait`::
Skip waiting for CI after push.

`--ci-fix-retries N`::
Maximum retries for fixing CI failures (default: 3).

`--ci-timeout N`::
Timeout in seconds for CI completion (default: 600).

`--isolate`::
Run inside an isolarium VM.

`--ignore-uncommitted-idea-changes`::
Skip validation that idea files are committed.

`--dry-run`::
Print what mode would be used and exit without executing.

== Description

The `implement` command reads a plan file from the idea directory and executes each task.
By default it operates in _worktree mode_: it creates a Git worktree on a feature branch, opens a GitHub Draft PR, executes each task with Claude, pushes changes, and waits for CI to pass.

When `--trunk` is specified, the command operates in _trunk mode_: it executes tasks directly on the current branch without creating a worktree, PR, or waiting for CI.

== Examples

[source,shell]
----
# Implement a plan using a worktree and Draft PR
i2code implement docs/features/my-feature

# Implement directly on the current branch
i2code implement docs/features/my-feature --trunk

# Set up infrastructure only (worktree, branch, PR) without running tasks
i2code implement docs/features/my-feature --setup-only

# Dry run to see what mode would be used
i2code implement docs/features/my-feature --dry-run
----

== `i2code scaffold` -- Project Scaffolding

The `scaffold` command generates project scaffolding for an idea directory.
It reads the plan and spec files and invokes Claude to produce initial project structure (directories, configuration files, and boilerplate).

=== Usage

[source,shell]
----
i2code scaffold <idea-directory> [options]
----

=== Options

`--non-interactive`::
Run Claude in non-interactive mode (uses the `-p` flag).

=== Example

[source,shell]
----
i2code scaffold docs/features/my-feature
----
